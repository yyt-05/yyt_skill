# 系统化代码审查维度

根据当前 diff 的真实影响选择适用维度。每个维度应给出代码、调用链、测试、配置或运行结果证据。

## 1. 需求与范围

- 改动是否满足真实需求和验收条件？
- 是否遗漏必要的调用方、入口或用户路径？
- 是否混入无关重构、命名、格式、依赖或基础设施变化？
- diff 是否小到能够可靠审查、独立验证和回滚？

## 2. 正确性与数据边界

- 正常、空值、缺失字段、非法类型、最大输入和脏数据行为是否明确？
- 单位、时区、编码、排序、去重、舍入和百分比转换是否一致？
- 分页、采样、截断和压缩是否披露完整性与原始/保留数量？
- 默认值是否掩盖错误或把不完整数据伪装成完整结果？
- 正则、解析、归一化和匹配是否可能误匹配或静默丢数据？

## 3. 上下游与接口契约

- 字段、类型、返回结构、错误语义、调用顺序和版本是否一致？
- 所有调用方、mock、动态引用和对外文档是否同步？
- HTTP、Webhook、SSE、消息和 CLI 的确认、超时、重试语义是否完整？
- 新实现是否复用已有负责人模块，而不是建立第二条路径？

## 4. 架构与依赖

- 代码是否位于真正负责该能力的模块？
- 依赖方向是否清楚，是否引入循环或反向依赖？
- 模块是否高内聚，还是把同一业务闭环拆散？
- `common`、`utils`、`manager` 等抽象是否具有明确边界和复用证据？
- 移动/重命名是否处理资源路径、模块双重加载和包初始化副作用？

## 5. 失败恢复与外部副作用

- 超时、部分成功、取消和异常分别如何传播？
- 重试是否幂等，是否会重复发消息、写库、部署或触发动作？
- 多步操作在中间失败后能否恢复一致状态？
- 错误是否被吞掉、改写或错误地降级为成功？
- 回滚条件、补偿动作和人工介入入口是否存在？

## 6. 并发、状态与生命周期

- 共享状态、缓存键和会话是否包含用户、租户、环境、任务等隔离维度？
- 锁、事务、原子操作、队列和容量预留是否覆盖全部失败路径？
- 重复请求、乱序事件、进程重启和多实例运行是否安全？
- 临时文件、任务、缓存、租约和连接是否清理或过期？
- 全局变量、ContextVar、线程本地状态和测试是否可能泄漏？

## 7. 安全、隐私与授权

- 外部入口是否具有鉴权、授权、来源验证和重放保护？
- 用户是否能通过修改 ID 访问其他用户、租户或环境的数据？
- 查询、路径、模板、Shell、URL、反序列化和日志是否存在注入风险？
- secret、内部 URL、生产 payload 和个人数据是否进入代码、fixture、日志或报告？
- 生产写入和危险动作是否有环境、权限、审批和审计门禁？

## 8. 性能、容量与成本

- 请求路径是否存在无界网络、文件、子进程、模型或数据库操作？
- 查询、列表、队列、缓存、日志和 payload 是否有上限、分页、过期和背压？
- 是否出现 N+1、重复查询、重复序列化或不必要的大对象复制？
- 异步/协程环境中是否混入阻塞调用？
- Token、模型调用、第三方 API、存储和传输成本是否可控？

## 9. 兼容、迁移与发布

- 数据库迁移是否幂等、向后兼容并考虑旧进程共存？
- 配置、环境变量、默认值和功能开关是否覆盖目标环境？
- API、事件、持久化数据和缓存格式升级是否有版本策略？
- Docker、Compose、脚本、工作流和仓库外入口是否同步？
- 能否渐进发布、监测、回滚，回滚后能否读取新数据？

## 10. 测试与证据质量

- 测试是否覆盖真实行为、边界、失败、重试和副作用？
- mock 是否指向运行时真正查找依赖的位置？
- 至少一个断言能证明目标路径确实执行，而非只断言 200/非空/关键词？
- fixture 是否接近生产结构、规模、顺序和脏数据？
- skip、flaky、平台差异和基线失败是否单独报告？
- 覆盖率是否针对新增/修改代码，而不是用全仓百分比掩盖缺口？

## 11. 可观测性与运维

- 日志、指标和 Trace 是否保留原始错误、请求标识和关键状态？
- 是否能区分成功、失败、降级、重试和不完整结果？
- 日志是否避免泄露敏感数据和无限增长？
- 健康检查是否反映真实依赖，而不是只证明进程存在？
- 告警和运行手册能否支持定位、止损和恢复？

## 12. 可维护性

- 名称、类型、注释和文档是否描述真实行为？
- 是否复用既有函数、常量和协议，而不是复制逻辑？
- 状态值、字段名、事件名和配置键是否集中定义？
- 防御性检查是否位于真实边界，而不是重复或永远无法命中？
- 兼容包装、抽象层和扩展点是否有真实调用方，而非为假想未来设计？

## 最后反证

审查结束前回答：

1. 什么输入、时序或环境最可能让该改动产生错误结果？
2. 在网络失败或进程重启时，是否可能重复副作用或留下半完成状态？
3. 攻击者或错误调用方最可能利用哪个信任边界？
4. CI 绿色仍可能漏掉什么？
5. 上线失败后，团队是否能观察、止损并回滚？
